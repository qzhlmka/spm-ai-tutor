# RAG Status — study-assistant (SPM tutor)

Current phase: 5 — Generation (Phase 4 passed 2026-10-13: kb_chunks loaded, 13,656 rows; pilot R@5 0.872 / MRR 0.766 via kb_search)

## Intake Brief (confirmed: yes, 2026-10-09)
- End goal: a Malaysian SPM student gets a correct explanation or worked solution, taught only from their teachers' notes, the KSSM textbooks and past-year papers, so they can see where every fact came from
- Users / channel: SPM students (Form 4–5) and their teachers; React web app (Supabase Auth login). Telegram planned (schema supports it)
- Success metric: ≥ 80% of answers graded correct by teachers in the weekly review
- Interaction type: tutor/coach (explain, work through past-year questions, read a photo of a question)
- Conversation: multi-turn (last 20 messages as history)
- Answer rules: sources listed under every answer (collapsed toggle); refuse when not in sources — strict grounding, facts only from retrieved material, reasoning on the student's own numbers allowed; reply in the student's language; step-by-step with KaTeX maths
- Sources / modalities: PDF textbooks (EN + BM), scanned past-year compilations and answer schemes, teacher-uploaded class notes (handwritten + slides), student photo/PDF attachments at chat time
- Route: mixed — OCR (`extractPagesVision`, gpt-4.1) for scanned and teacher material; text layer for clean textbooks
- Volume / freshness: ~10.6k chunks across Chemistry, Physics, Mathematics, Add Maths, Sejarah (~2.4k past-year questions, 108 teacher files); teachers upload continuously, textbooks one-off
- Languages: Malay and English, mixed within a subject (Maths/Physics/Add Maths mostly English, Sejarah and teacher notes mostly Malay)
- Access control: none per user — all material is one shared pool for logged-in users; uploads teacher-only
- Constraints: student cap $0.20/day; latency p95 ≤ 20s for a schoolwork turn, ≤ 6s for chat (proposed — measured today ~15s and ~5s); privacy — users are school students, Langfuse on the Japan region
- Reviewers / cadence: teachers — AI judge daily, human queue weekly (40), golden refresh monthly
- Traffic / growth: over 2,000 students within 12 months; corpus grows with teacher uploads (pgvector is ample at this size; cost per turn matters more than store choice)
- Targets: Recall@5 0.85 | MRR 0.70 | Faithfulness 0.90 | Correctness 0.80 | Refusal 0.90

## Current pipeline config
- Loader(s): pdf-parse (text layer) or pdftoppm + gpt-4.1 vision OCR; bespoke past-year scripts per subject
- Chunking: LLM chunker (gpt-4.1), 6-page batches, typed chunks (concept / worked_example / past_year_question / formula / common_mistake)
- Embeddings: multilingual-e5-base, local via @huggingface/transformers (768-d, int8)
- Retrieval switch: `RETRIEVAL_BACKEND` = content_chunks (default, live) | kb_chunks (src/lib/kb-search.ts). On kb_chunks the 3 whole-KB lanes call kb_search main (combined 10, bare 5, Malay rewrite 5) + a past_year lane (2, end of block; off when the exam lane fires or the subject is unknown). Teacher vector + judge, teacher lexical and exam lanes stay on content_chunks. Carried rows use legacy_chunk_id as their id so they dedupe with those lanes.
- Retrieval: 6 lanes — whole-KB vector ×3 (combined, bare, Malay→English rewrite), teacher vector + LLM relevance judge, teacher lexical (IDF), exam-label filter; merged to 12 chunks
- LLM (generate / judge): Claude Sonnet 5 default, GPT and IlmuChat selectable; judges and router on Claude
- Prompts: in code (`chat-handler.ts`, `router.ts`) — not in Langfuse
- Graph nodes: route → retrieve | catalogue → exam_images / materials / resources → compose → provider → generate → persist → visual (`src/lib/chat-graph.ts`)

## Notes for Phase 5
- **Judge harness bug (found 2026-10-13):** every v3 run before p5-exam-order-rejudge scored 6–10 answerable items 0 faithfulness / 0 correctness because the judge's claims JSON could not be parsed (stop_reason tool_use, not truncation). Those runs' absolute numbers (A, B, C, grounding-precision, lexical-judged, exam-order) are biased low by up to ~0.14 correctness and ~0.1 faithfulness, and their item-level "flips" were largely this bug, not judge noise. Fixed in eval-answers.ts (retry ×3, exclude still-failed, max_tokens 6000). Earlier keep/revert decisions should be confirmed by re-judging those runs (`--reuse`, ~$1–1.5 each).
- Judge (2026-10-13): one 0/1 faithfulness verdict per answer was too noisy to separate 0.88 from 0.90 (v1 vs v2: 11/82 flipped). answer-judge v3 lists every factual claim as stated (verbatim quote, checked in code by 3-gram overlap ≥ 0.5 or 90% word coverage) / derived / unsupported; faithfulness = share of supported claims. Two runs: 0.875 and 0.875. Known residual bias: still flags some one-step derivations (marathon v·t = 42) and misses some table facts (Ohm's law p112), so it reads slightly low. Correctness under v3 (0.77) is lower than v1 (0.88) and flips on ~18% of items run to run — treat correctness differences under ~0.03 as noise.
- Run A failure types (2026-10-13): (1) mechanism elaborated from the model's own knowledge when the page only poses the question (Daniell cell, candle flame, heat-loss modes, teknik U example, colour blindness while declining); (2) false refusals — would not check a student's own algebra ("x-3=5 … x=2, betul?"), sidetracked on a date technicality (harga barang), asked for clarification on "apa formula anode"; (3) Add Maths F5 topic list asked with no Add Maths retrieved — in the live app this goes to the catalogue route; the eval harness bypasses the router.
